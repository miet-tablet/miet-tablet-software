# Ёмкостный тачскрин GSL1680F для ER-TPC050A2-1

Модуль предназначен для комплектации дисплея **ER-TFT050-6-6428 с ёмкостной панелью**.
Изображение выводит RA8875 по SPI2, касания обрабатывает отдельный GSL1680F по I²C.

## Пример подключения STM32H7B0VBT6

| Контакт JP1 | Сигнал | Пин STM32 (пример) |
| --- | --- | --- |
| 33 | CTP_INT | пока не подключается: в тесте polling |
| 34 | CTP_SDA | PB9 / I2C1_SDA, AF4 |
| 35 | CTP_SCL | PB8 / I2C1_SCL, AF4 |
| 36 | CTP_/RST | PC6 / GPIO, активный низкий уровень |

Обязательно общая земля и уровни сигналов **3,3 В**. Для SDA/SCL нужны
подтяжки к 3,3 В (например, 4,7 кОм, если их нет на плате модуля).
Драйвер RA8875 использует SPI2 (PB12–PB15), а тестовый светодиод на WeAct — PE3.
Перед реальным подключением необходимо проверить доступность пинов на плате.
Нельзя подавать 5 В на линии GSL1680F.

## Firmware GSL1680F — обязательная зависимость

Контроллеру требуется загрузка firmware, **соответствующей конкретной панели**.
В этой версии уже включён образ **gslX680_311_5_F.h**, предоставленный для
GSL1680F / 800×480, и преобразованный в массив `gsl1680_firmware[]`.
**Перед публикацией в общем репозитории согласуйте с командой условия
распространения firmware производителя.** Совместимость с конкретной
аппаратной модификацией всё равно нужно проверить на реальном устройстве.

1. При необходимости заново скачать файл производителя `gslX680_311_5_F.h`:
   https://www.buydisplay.com/5-inch-capacitive-touch-panel-screen-with-controller-gsl1680f
2. Из корня репозитория выполнить:

   ```bash
   python3 tools/gsl1680_fw_convert.py ~/Загрузки/gslX680_311_5_F.h
   ```

   При английском названии папки заменить `Загрузки` на `Downloads`.
3. Конвертер перезапишет `firmware/touch_gsl1680/src/touch_gsl1680_firmware.c`.
   Текущий файл уже сгенерирован из приложенного пользователем образа.
   Проверить происхождение и условия распространения перед публикацией.
4. Проверить размер полученной программы, так как внутренняя Flash H7B0 — 128 КиБ.

Конвертер рассчитан на формат производителя `GSLX680_FW[]` с записями
`{0xF0, 0x00000003}, {0x00, 0xA5A5FFC0}, ...`. Значение 0xF0 переключает
страницу памяти. Не следует подставлять firmware от другой сенсорной панели.

## Сборка и проверка

Создать свою ветку **на основе** `origin/kirill_gr.display_ra8875`, применить
патч и собрать тест:

```bash
make clean
make top=test_touch_gsl1680
make upload-dfu
```

Тест включает RA8875, проверяет I2C-контроллер, загружает firmware и каждые
25 мс читает первое касание. При перемещении пальца на экране появляются
зелёные точки. Текущие значения можно смотреть в отладчике:
`touch_x`, `touch_y`, `touch_contacts`, `touch_pressed`, `touch_driver_error`.

Пока не пройдена инициализация, светодиод выдаёт N коротких вспышек и паузу:

| `touch_test_stage` | Значение |
| --- | --- |
| 0 | всё запущено, выполняется polling |
| 1 | RA8875 не инициализировался |
| 2 | ошибка I2C1 или неверная частота PCLK1 |
| 4 | GSL1680F не ответил по I²C (адрес 0x40) |
| 5 | пустой firmware-образ (актуальная сборка содержит непустой) |
| 6 | сбой начальной настройки регистров |
| 7 | ошибка загрузки firmware |
| 8 | ошибка запуска прошивки контроллера |
| 9 | сигнатура готовности не равна `5A 5A 5A 5A` |
| 10 | не удалось прочитать данные касания |

В успешном режиме светодиод переключается примерно каждые 25 мс. Это не
заменяет проверки картинки и линий I²C на настоящем оборудовании.

## API и ограничения

```c
int gsl1680_init(gsl1680_t *dev,
                 const gsl1680_fw_entry_t *fw, size_t fw_count);
int gsl1680_read(gsl1680_t *dev, gsl1680_touch_t *touch);
```

Чтение идёт из блока регистров `0x80–0x87`: число касаний и координаты первого
пальца. Пока реализована **одна точка**, хотя `contacts` сообщает общее число.
Обработка жестов не требуется для первого этапа. Сырые координаты нужно
сверить с ориентацией панели; в тесте есть `TOUCH_SWAP_XY`,
`TOUCH_INVERT_X`, `TOUCH_INVERT_Y`.

В примере I2C1 настроен на PB8/PB9. Регистр таймингов `0xD0622C36`
рассчитан **предварительно** для тактирования периферии 140 МГц и порядка
100 кГц; реальную частоту и фронты надо проверить осциллографом/анализатором
и уточнить через CubeMX под плату.

Текущий `firmware/i2c_wheels` передаёт адрес устройства `0`, поэтому для
тача временно используется прямой HAL I2C. Позже можно согласовать доработку
общего API с командой (передача адреса устройства).

Функция `gsl1680_init` проверяет сигнатуру готовности `0xB0 = 0x5A5A5A5A`.
Возвраты `0` — успех; `-1` — некорректные аргументы, `-2` — нет ACK,
`-3` — нет firmware, `-4` — ошибка регистров, `-5` — ошибка загрузки,
`-6` — ошибка запуска, `-7` — нет ожидаемой сигнатуры.
`gsl1680_read` возвращает `-2` при ошибке I²C и `-3` при неверном количестве
касаний.

**До получения и проверки панели это прототип, а не подтверждённый драйвер.**

## Отличия от примера Linux производителя

Оригинальный `sunplus_gslX680.c` рассчитан на Linux, не STM32 HAL.
Он подключает `gslX680_311_5_E.h`, а доступный образ называется
`gslX680_311_5_F.h`. Для загрузки используется именно образ F
(4 323 записи, в C-массиве порядка 34 КБ на ARM); необходимо
проверить соответствие купленному сенсорному стеклу. Переключение
страницы `0xF0` передаётся одним байтом, слова прошивки — 4 байтами.

Успешная компиляция не подтверждает инициализацию GSL1680F на реальном устройстве.
