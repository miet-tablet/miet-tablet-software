# Как правильно коммитить в проект

Для внесения изменений в код создаем свою ветку. Название ветки — ваше имя/фамилия/ник, через точку название самой ветки. Например, victor_k.dev.

Проект строится как набор программных модулей. Модуль — это папка, в которой есть директории `inc`, `src` и файл `CMakeLists.txt`. В папке `inc` должны храниться Си-заголовки (.h), в папке `src` - исходники (.c). `CMakeLists.txt` - файл, в котором говорится, как собирать модуль.

Пример простейшего модуля:

```
my_module
├─ inc
|  ├─ my_module.h
├─ src
|  ├─ my_module.c
├─ CMakeLists.txt
```

**Как оформлять заголовки?**

Заголовки должны содержать вначале строку `#pragma once`. Она говорит компилятору, что заголовок надо обработать лишь единожды, это избавит нас от ошибки multiple function declaration. Затем идут инклуды, потом - прототипы функций. Обычно названия встроенных в Си библиотек вроде `stdint.h` или `stdio.h` пишут в угловых скобочках, пользовательские заголовки оформляют в кавычки. Пример файла-заголовка:

```
#pragma once

#include <stdint.h>
#include "another_user_header.h"

uint32_t my_function(uint32_t);

```

**Как оформлять исходники?**

Крайне рекомендуется соблюдать правило, по которому каждому Си-файлу соответсвует заголовок и наоборот. Также, инклуды сторонних модулей и стандартных библиотек должны быть в заголовке, а в Си-файле должен быть только один инклуд, заголовка с именем файла. Пример для файла `my_module.c`:

```
#include "my_module.h"

uint32_t my_function(uint32_t)
{
    ...
}

```

**Как писать CMakeLists.txt?**

`CMakeLists.txt` - это особое название файла конфигурации CMake. CMake - это утилита, которая облегчает сборку Си-кода. Она ищет в директориях файлы `CMakeLists.txt` и собирает код, исходя из инструкций в них. Язык скриптов CMake - декларативный, чем-то напоминает по логике Postgres.

Оформлять файлы `CMakeLists.txt` для модуля предлагаю по шаблону. Для нашего модуля `my_module`:

```
project(my_module)

set(SOURCES
    src/my_module.c
)

add_library(${PROJECT_NAME} STATIC ${SOURCES})

target_include_directories(${PROJECT_NAME} PUBLIC inc)

target_link_libraries(${PROJECT_NAME}
    PUBLIC
        CMSIS_Core
        STM32H7xx
        STM32H7xx_HAL_Driver
)
```

По строчкам: сначала указываем название "проекта" (модуля), затем определяем, какие исходники надо собирать, далее говорим, что будем собирать статическую (.a) библиотеку, далее говорим, что в директории `inc` содержатся заголовки, которые надо инклудить, ну и в финале указываем, с какими другими модулями нужно линковать наш.

Зачем указывать, с чем линковать, если мы все равно линкуем один раз все вместе в самом конце сборки? Последняя команда `target_link_libraries` нашему модулю нужна, чтобы добавить в область видимости нашего модуля заголовки других модулей. Также эта команда нужна, чтобы дать CMake'у понять, какие зависимости есть в коде, чтобы он вообще понял, что с чем линковать в финале. Как-то так.
